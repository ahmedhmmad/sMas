## 1. النموذج

### 1.1 `calendar_weekdays` — [S عبر السنة]

أيام الدوام الأسبوعية لسنة بعينها (الثابت 15).

| العمود | النوع | ملاحظات |
|---|---|---|
| `id` | uuid | PK |
| `school_id` | uuid | من صف السنة |
| `academic_year_id` | uuid | FK مركّب `(academic_year_id, school_id)` |
| `weekday` | smallint | **0 = الأحد … 6 = السبت** (`extract(dow)`)؛ CHECK 0..6 |
| `status` | text | `active` \| `inactive` — لا DELETE: إزالة يوم = `inactive` |
| المشتركة | | T6/T7 |

قيود: فريد `(academic_year_id, weekday)`. **لا منح كتابة للعميل**: التغيير بالدالة `app.set_calendar_weekdays` وحدها (عملية مجموعة ذرية — لا loop من الـAPI).

### 1.2 `calendar_exceptions` — [S عبر السنة]

| العمود | النوع | ملاحظات |
|---|---|---|
| `id` | uuid | PK |
| `school_id`, `academic_year_id` | uuid | |
| `year_start_date`, `year_end_date` | date | نسخة حدود السنة — FK مركّب إلى `academic_years` **`ON UPDATE CASCADE`** (نمط `terms`/I35): تعديل تواريخ سنة `planned` يُرفض إن خرج استثناء عن الحدود |
| `kind` | text | `holiday` \| `study_day` |
| `name` | text | غير فارغ |
| `start_date`, `end_date` | date | `start ≤ end`؛ داخل حدود السنة (CHECK)؛ `study_day` ⇒ `start = end` (C5) |
| `status` | text | `active` \| `cancelled` — **الإلغاء نهائي** (لا إعادة تنشيط؛ استثناء جديد بدلاً منه) |
| المشتركة | | T6/T7 |

قيود: **EXCLUDE** — لا تداخل بين عطلتين نشطتين في السنة نفسها (`daterange` بـ`&&`، شرط `kind = 'holiday' and status = 'active'`)؛ فريد جزئي — يوم استثنائي نشط واحد لكل تاريخ. اليوم الاستثنائي **داخل** عطلة مسموح (ذلك معناه).

**المنح:** INSERT `(school_id, academic_year_id, year_start_date, year_end_date, kind, name, start_date, end_date)` — الـAPI يملأ المدرسة والحدود من صف السنة المقروء تحت RLS؛ UPDATE `(name, start_date, end_date, status)` تحت الحارس؛ لا DELETE.

| | قراءة | كتابة |
|---|---|---|
| الجدولان | `can_access_school(school_id)` + `academic_year.read` (المعلم والسكرتير والمحاسب والمرشد والمديرون) | `… + academic_year.update` (المديرون الثلاثة) |

## 2. الحارس T14 — قواعد B8 كما ستُنفَّذ

`T` = «اليوم» بتوقيت المدرسة (C1). الحارس `BEFORE INSERT OR UPDATE` على `calendar_exceptions`، `SECURITY DEFINER`، الرفض `23514` (والسبب الغائب `22023`)، على كل مسار.

| حالة السنة | INSERT | UPDATE لاستثناء بدأ في `≥ T` | UPDATE لاستثناء بدأ في `< T` (C4) | الإلغاء |
|---|---|---|---|---|
| `planned` | حر | حر | حر (السنة لم تبدأ تشغيلياً) | حر |
| `active` | `start_date ≥ T` + **سبب** (C3) | البداية الجديدة `≥ T` + سبب | `end_date` وحده، والقديم والجديد `≥ T` + سبب؛ غيره مرفوض | `start_date ≥ T` + سبب؛ وإلا مرفوض |
| `closed` | مرفوض | مرفوض | مرفوض | مرفوض |

ودائماً: الهوية (`school_id`, `academic_year_id`, `kind`) ثابتة؛ `cancelled` نهائي؛ C5 يُفحص عند إنشاء يوم استثنائي أو نقل تاريخه.

**أيام الدوام — `app.set_calendar_weekdays(year, weekdays smallint[], reason)`:** `academic_year.update` + نطاق؛ `planned`: تُضبط المجموعة كما هي (إضافة `active`، والغائب `inactive`)؛ `active`: **فقط إن كانت المجموعة الحالية فارغة** (C2) وبسبب، وإلا مرفوض؛ `closed`: مرفوض؛ مجموعة فارغة أو قيمة خارج 0..6 ← `22023`؛ تدقيق domain + T7.

## 3. «هل اليوم دراسي؟» — العقد الذي تستهلكه المرحلة 5

`app.is_school_day(p_school uuid, p_date date) returns boolean` — دالة **واحدة**، بلا آثار، `SECURITY INVOKER`، **بلا EXECUTE لأدوار الـAPI** في 2B (أداة داخلية تستدعيها دوال المرحلة 5 المتحكَّم بها؛ القراءة للواجهة عبر الجدولين تحت RLS):

```text
السنة = سنة المدرسة التي تحتوي التاريخ (السنوات لا تتداخل — 2A)
لا سنة                                          → false
يوم استثنائي نشط في التاريخ                     → true
عطلة نشطة تغطي التاريخ                          → false
يوم الأسبوع من أيام الدوام النشطة للسنة          → true
غير ذلك                                          → false
```

حالة السنة لا تدخل في الحساب (السنة المغلقة تعطي تاريخها كما كان)؛ الإلغاء يُخرج الاستثناء من الحساب.

## 4. النسخ (B13)

`app.copy_calendar_weekdays(source, target, reason)` — عقد M37/M40 حرفياً: الهدف `planned` في المدرسة نفسها؛ المفتاح `(target_year, weekday)`؛ المطابق (`active`) «منسوخ سابقاً»؛ يوم موجود معطَّل حيث المصدر نشط ← يُفشل الكل؛ الإضافي في الهدف لا يُمس؛ سبب؛ صف domain. **الاستثناءات المؤرخة لا تُنسخ** (B13).

## 5. الـAPI والواجهة

| المسار | العملية |
|---|---|
| `GET /academic-years/{id}/weekdays` | قراءة |
| `PUT /academic-years/{id}/weekdays` `{weekdays, reason?}` | `set_calendar_weekdays` |
| `POST /academic-years/{id}/copy-weekdays` `{source_year_id, reason}` | `copy_calendar_weekdays` |
| `GET/POST /academic-years/{id}/calendar-exceptions` `{…, reason?}` | قراءة / إنشاء (المدرسة والحدود من صف السنة) |
| `PATCH /calendar-exceptions/{id}` `{name?, start_date?, end_date?, reason?}` | تعديل |
| `POST /calendar-exceptions/{id}/cancel` `{reason}` | `status = cancelled` |

السبب اختياري في الـschema؛ **القرار في DB** (C3). القواعد العامة كما 2A: 404/403، `extra="forbid"`، لا DELETE.

**الواجهة — بطاقة «التقويم» في صفحة السنة:** أيام الأسبوع (مربعات + حفظ، وحقل سبب للسنة النشطة)؛ قائمة الاستثناءات (نوع، اسم، فترة، حالة) + إضافة + إلغاء؛ عرض شهري بسيط للقراءة. الحقول المقفلة حسب الحالة والتاريخ **عرض فقط** — الحارس هو الحكم.

## 6. الاختبارات (Gate)

- **pgTAP:** كل خلية في جدول §2 بالرسالة/القيد (ومنها حدود `T` نفسها: اليوم، الأمس، الغد)؛ EXCLUDE باسمه؛ حدود السنة وتسلسل `ON UPDATE CASCADE`؛ C2 (التعريف الأول في سنة نشطة مرة واحدة)؛ C5؛ `is_school_day` لكل فرع (لا سنة، يوم استثنائي داخل عطلة، عطلة، يوم دوام، يوم راحة، استثناء ملغى، سنة مغلقة)؛ عزل المدرسة/الـTenant؛ القراءة ≠ الكتابة؛ التدقيق والسبب؛ «اليوم» بتوقيت المدرسة (مدرسة بتوقيت مختلف)؛ النسخ (عقد M40).
- **ضوابط سلبية:** حذف كل شرط من الحارس والدوال واحداً واحداً.
- **pytest / Vitest / Playwright:** المسارات، السبب من الجسم يصل إلى التدقيق، الرفض بلا سبب في سنة نشطة، تجاوز الواجهة لا يمنح شيئاً.
- **الحراس الدائمة:** `11` (T7 على 34)، `13` (34 جدولاً)، `20` (سجل الأعمدة + allowlist)، `31`، الاستعادة.

## 7. ما لا يدخل 2B-2

الحضور وأثر العطلة عليه (المرحلة 5)؛ قرار مصير حضور يومٍ صار عطلة (المرحلة 5 — C1)؛ العطل الرسمية الموحدة على مستوى الـTenant أو المجموعة (لا مصدر بيانات لها بعد)؛ ربط الفصول الدراسية بالتقويم؛ الدوام والحصص (2B-3).
