# Phase 2B-3 — الدوام والحصص: وثيقة التصميم — Design Gate

**التاريخ:** 2026-10-05
**الحالة:** ⏳ **بانتظار الاعتماد** — لا SQL ولا كود قبل اعتماد القرارات D1–D7
**خط الأساس:** 2B-2 مغلقة (CI `c5a0aaf`)؛ 47 migration (M01–M42)؛ الكتالوج 75
**المرجع:** `docs/PHASE2B_SCOPE.md` §0 (B11، B12، B13) و§4؛ `docs/PHASE2B_2_CALENDAR.md` (أيام الدوام، C3)؛ `CLAUDE.md` §1 (الثابت 15)، §5 (الحضور يومي فقط في v1)

> **الغرض:** تعريف **الفتحات الزمنية** لكل يوم دراسي — الحصص والاستراحات بأوقاتها — لكل فترة دوام في السنة، بحيث تكون أساساً مباشراً للجدول الدراسي (المرحلة 11، OR-Tools) **دون إعادة تصميم**. لا ربط بالحضور (v1: حضور يومي فقط).

## 1. النموذج

### 1.1 `bell_schedules` — [S عبر السنة]

جدول دوام = **فترة** (صباحية، مسائية…) في سنة بعينها (B11، الثابت 15).

| العمود | النوع | ملاحظات |
|---|---|---|
| `id` | uuid | PK |
| `school_id`, `academic_year_id` | uuid | FK مركّب `(academic_year_id, school_id)` |
| `name` | text | فريد في السنة؛ غير فارغ |
| `status` | text | `active` \| `inactive` — لا DELETE |
| المشتركة | | T6/T7 |

### 1.2 `bell_periods` — [S عبر السنة] (D1، D5، D6، D7)

| العمود | النوع | ملاحظات |
|---|---|---|
| `id` | uuid | PK — **المعرّف الثابت للفتحة** في المرحلة 11 |
| `school_id`, `academic_year_id`, `bell_schedule_id` | uuid | FK مركّب إلى الجدول بمدرسته وسنته |
| `weekday` | smallint | 0..6 (اصطلاح M41)؛ يوم دوام نشط (D4) |
| `kind` | text | `lesson` \| `break` (D7) |
| `name` | text | اختياري للحصة (يُعرض الرقم المشتق)، إلزامي للاستراحة |
| `start_time`, `end_time` | time | `start < end` (لا عبور لمنتصف الليل) |
| `status` | text | `active` \| `inactive` — الإزالة = `inactive` |
| المشتركة | | T6/T7 |

قيود: `EXCLUDE` — لا تداخل بين حصتين نشطتين في (الجدول، اليوم) (D6)؛ الحدود الملاصقة (نهاية = بداية التالية) **ليست** تداخلاً (`[)`).

### 1.3 `grade_level_bell_schedules` — [S عبر السنة] (D2)

| العمود | النوع | ملاحظات |
|---|---|---|
| `id` | uuid | PK |
| `school_id`, `academic_year_id`, `grade_level_id`, `bell_schedule_id` | uuid | FKs مركّبة بالمدرسة؛ الجدول من السنة نفسها |
| المشتركة | | T6/T7 |

فريد `(academic_year_id, grade_level_id)` — صف واحد ← جدول واحد في السنة. تغيير الإسناد = UPDATE لـ`bell_schedule_id` (لا DELETE).

### 1.4 الملكية والتفويض (B12)

قراءة: `can_access_school` + `academic_year.read` (المعلم والسكرتير والمحاسب والمرشد والمديرون — B15)؛ كتابة: `… + academic_year.update`. **لا مفتاح جديد** — الكتالوج يبقى 75.

## 2. الحارس T15 — قواعد الحالة على كل مسار

نمط T12–T14 (`SECURITY DEFINER`، `23514`، السبب الغائب `22023`):

| | `planned` | `active` | `closed` |
|---|---|---|---|
| الجداول والحصص والإسناد | حر | مسموح **بسبب** (D3) | مجمَّد |

ودائماً:
- الهوية ثابتة: الحصة لا تنتقل إلى مدرسة/سنة/جدول آخر، والجدول لا ينتقل إلى سنة أخرى.
- **الحصة النشطة على يوم دوام نشط** للسنة (D4، عند الإنشاء وإعادة التفعيل وتغيير اليوم)؛ والجهة الثانية في `set_calendar_weekdays`.
- **الحصة النشطة تحت جدول نشط**؛ ولا يُعطَّل جدول مُسنَد إليه صف (يُعاد إسناد الصف أولاً) — الإسناد لجدول نشط فقط.
- الإسناد: الصف نشط، والجدول من سنة الإسناد نفسها.

## 3. النسخ (B13)

`app.copy_bell_schedules(source, target, reason)` — عقد M37/M40/M42، **ذرياً للثلاثة معاً**: الجداول (المفتاح `(year, name)`)، حصصها النشطة (المفتاح `(schedule, weekday, start_time)` — المطابقة = النوع والنهاية والاسم)، وإسناد الصفوف النشطة (المفتاح `(year, grade_level)` — المطابقة = الجدول نفسه بالاسم). المطابق «منسوخ سابقاً»؛ أي اختلاف يُفشل الكل؛ الحصص على أيام ليست أيام دوام **في السنة الهدف** تُرفض صراحةً (D4 — لذا تُنسخ أيام الدوام أولاً، M42)؛ الهدف `planned`؛ سبب؛ صف domain.

## 4. أساس المرحلة 11 (النقطة 7) — ما يحصل عليه المولّد دون إعادة تصميم

| ما يحتاجه OR-Tools | مصدره بعد 2B-3 |
|---|---|
| الفتحات لكل شعبة | الشعبة ← صفها ← `grade_level_bell_schedules` ← `bell_periods` (`lesson`، نشطة) لكل يوم دوام |
| هوية الفتحة الثابتة | `bell_periods.id` (+ الرقم المشتق للعرض) |
| عدد الفتحات الأسبوعية المتاح | عدّ الحصص النشطة من نوع `lesson` للجدول |
| الطلب: حصص كل مادة | `grade_subjects.weekly_periods` (2B-1) |
| الأيام الدراسية الفعلية | `is_school_day()` (2B-2) |

**ما يبقى للمرحلة 11:** المعلمون وتكليفاتهم (3)، القاعات، الجدول نفسه وقفله للحصص المستخدمة. لا جدول ولا عمود في 2B-3 يُعاد تصميمه لذلك.

## 5. الـAPI والواجهة

| المسار | العملية |
|---|---|
| `GET/POST /academic-years/{id}/bell-schedules` · `PATCH /bell-schedules/{id}` | الجداول (`reason?` في الجسم — DB تقرر) |
| `GET/POST /bell-schedules/{id}/periods` · `PATCH /bell-periods/{id}` | الحصص |
| `POST /bell-schedules/{id}/copy-day` `{from_weekday, to_weekdays, reason?}` | نسخ يوم إلى أيام **داخل الجدول** — عملية واحدة في DB (`app.copy_bell_day`): الأيام الهدف بلا حصص نشطة وإلا رفض (لا دمج صامت) |
| `GET /academic-years/{id}/grade-bell-schedules` · `PUT /academic-years/{id}/grade-bell-schedules/{grade_level_id}` `{bell_schedule_id, reason?}` | الإسناد |
| `POST /academic-years/{id}/copy-bell-schedules` `{source_year_id, reason}` | النسخ (B13) |

القواعد العامة كما 2A/2B: 404/403، `extra="forbid"`، لا DELETE، السبب من الجسم إلى `app.audit_reason` (C3).

**الواجهة — بطاقة «الدوام» في صفحة السنة:** الجداول؛ لكل جدول شبكة يوم × خط زمني (الحصص مرقّمة اشتقاقاً، الاستراحات باسمها)؛ إضافة/تعديل/تعطيل حصة؛ «نسخ هذا اليوم إلى…»؛ إسناد الصفوف؛ نسخ من سنة سابقة.

## 6. الاختبارات (Gate)

- **pgTAP:** EXCLUDE باسمه (وتلاصق الحدود ليس تداخلاً، وجدولان يتداخلان مشروعاً — D6)؛ `start < end`؛ D4 من الجهتين (حصة على يوم ليس دوامًا ← رفض؛ تعطيل يوم دوام له حصص ← رفض)؛ الحصة تحت جدول نشط، ولا تعطيل لجدول مُسنَد؛ الإسناد الفريد والصف النشط؛ الحالات الثلاث (D3، والسبب على كل مسار)؛ الهوية؛ `copy_bell_day` (لا دمج صامت)؛ النسخ (عقد M42 + الأجزاء الثلاثة ذرياً + الأيام في الهدف)؛ العزل والقراءة ≠ الكتابة؛ التدقيق.
- **ضوابط سلبية** لكل شرط.
- **pytest / Vitest / Playwright:** المسارات، يوم مختلف العدد (D1)، فترتان (D6)، السبب في السنة النشطة، تجاوز الواجهة لا يمنح شيئاً.
- **الحراس الدائمة:** `11`، `13` (37 جدولاً)، `20`، `31`، الاستعادة.

## 7. ما لا يدخل 2B-3

الجدول الدراسي ومولّده (11)؛ المعلمون والقاعات (3، 11)؛ الحضور بالحصة (ممنوع في v1)؛ **جداول مؤقتة بمدى تواريخ** (رمضان، امتحانات) — تُصمَّم مع المرحلة 11 أو قرار لاحق، وحتى ذلك الحين تعديل الجدول النشط بسبب (D3) يغطيها؛ إسناد الشعبة منفردة (D2-أ) — قابل للإضافة لاحقاً فوق إسناد الصف.
