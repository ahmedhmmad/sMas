## 1. القرارات المطلوبة (E1–E10)

| # | السؤال | المقترح | البديل | لماذا |
|---|---|---|---|---|
| **E1** | الملف: لكل سنة أم للمدرسة؟ وماذا تطبع شهادة قديمة؟ | **للمدرسة، غير مُنسَخ** (العنوان، الهاتف، البريد…). ما تطبعه وثيقة رسمية (اسم المدير، نسخة الختم) **تلتقطه الوثيقة نفسها لحظة إصدارها** — المرحلة 6 | ملف لكل سنة دراسية | الثابت 15 للإعدادات المؤثرة على **الحسابات**؛ بيانات التواصل ليست كذلك. التاريخ الصحيح للشهادة = لقطتها، لا ملف مُنسَخ |
| **E2** | تعريف التوقيع | **صفة نصية حرة** (`signer_title`، مثل «مدير المدرسة»)؛ نشط واحد لكل (مدرسة، صفة مُطبَّعة: `lower(btrim())`) | قائمة صفات ثابتة بـCHECK | الصفات تختلف بين المدارس (وكيل، مدير مرحلة، شؤون طلاب)؛ القائمة الثابتة تحتاج migration لكل صفة. قالب الشهادة (6) يختار **الأصل** لا الصفة |
| **E3** | التقاعد مقابل الحذف | **لا حذف إطلاقاً من التطبيق — لا للصف ولا للكائن.** التقاعد = `retired` + `retired_at`؛ نهائي (لا إعادة تنشيط — العودة = رفع جديد)؛ الكائن يبقى (الشهادات القديمة تشير إليه). الحذف الفعلي الوحيد: **تعويض الـSaga** لكائن رفعته الخدمة في الطلب نفسه ولم يُسجَّل صفه | حذف الكائن عند التقاعد | الشهادة الصادرة بنسخة ختم يجب أن تبقى قابلة للعرض والتحقق. سياسة الاحتفاظ/الإتلاف = Production Readiness |
| **E4** | مسار الكائن | `{platform_tenant_id}/{school_id}/{kind}/{asset_id}.{png\|jpg}` — **معرّفات لا slugs**؛ `asset_id` يولده FastAPI قبل الرفع ويصبح PK الصف (نمط D1)؛ CHECK في DB يطابق المسار مع الصف حرفياً | `{tenant_label}/{slug}/…` | الـslug يتغير (M36) والمعرّف لا؛ المطابقة الحرفية تجعل تزوير مسار يشير إلى مدرسة أخرى مستحيلاً حتى لو أخطأ الـAPI |
| **E5** | ترتيب الـSaga | **DB أولاً:** في معاملة المستخدم: `app.register_school_asset(...)` (يتحقق من الصلاحية والنطاق والحالة ويكتب الصف ويُحيل السابق) ← **لا commit** ← رفع الكائن ← commit. فشل الرفع ← rollback (لا صف)؛ فشل الـcommit ← حذف الكائن (تعويض). **من لا يملك الصلاحية لا يرفع بايتاً واحداً** | Storage أولاً ثم DB | المقترح يجعل «صف بلا كائن» مستحيلاً و«كائن بلا صف» محصوراً في فشل نادر بعد الرفع — ويكشفه فحص الاتساق (E9) |
| **E6** | التحقق من الملف | **من البايتات لا من العميل:** التوقيع السحري (PNG `89 50 4E 47`، JPEG `FF D8 FF`)، الأبعاد من الترويسة (≤ 4000×4000)، الحجم ≤ 1MB؛ `content_type` يُحدَّد من التوقيع لا من الطلب؛ اسم الملف من العميل **يُهمل**؛ `sha256` يُحسب في الخادم ويُخزَّن. **بلا إعادة ترميز وبلا مكتبة صور** (قراءة الترويسة يدوياً ~40 سطراً) | Pillow لفك الصورة وإعادة ترميزها | إعادة الترميز تُسقط أي حمولة مخبأة لكنها dependency كبيرة نسبياً (C)؛ الملف لا يُقدَّم إلا برابط موقّع بـ`content-type` صورة من bucket خاص، فالخطر محدود. يمكن إضافة إعادة الترميز لاحقاً بقرار |
| **E7** | قراءة الأصول | **البيانات الوصفية** (النوع، الصفة، الحالة، التاريخ): `school.read` + النطاق. **الرابط الموقّع:** الشعار `school.read`؛ **الختم والتوقيعات `security.manage`**. مدة الرابط **60 ثانية** | روابط لكل من يرى المدرسة | عرض صورة الختم لكل موظف يقرأ المدرسة = نسخها؛ من يحتاج رؤيتها هو من يديرها. الشهادات (6) تُركَّب في الخادم لا بروابط للعميل |
| **E8** | تدقيق الوصول | T7 على الجدولين (الإنشاء، التقاعد، تعديل الملف) بالسبب؛ **إصدار رابط موقّع للختم أو التوقيع يُدقَّق** (صف `asset_url` في المعاملة نفسها، fail closed — نمط تدقيق القراءة في F4)؛ رابط الشعار لا يُدقَّق | تدقيق كل رابط، أو لا تدقيق للقراءة | الوصول إلى صورة الختم حدث أمني؛ الشعار عام بطبيعته |
| **E9** | الاتساق وحدود الاستعادة | دالة داخلية `app.school_asset_consistency()` تقارن الصفوف بـ`storage.objects` (الجدول في قاعدة البيانات نفسها) وتعيد: صف بلا كائن، كائن بلا صف في الـbucket. **قابلة للاختبار في CI** (pgTAP يدرج صفوفاً في `storage.objects` مباشرة). اختبار الاستعادة المحلي يضيفها. **محتوى الكائنات خارج `pg_dump`** — نسخه الاحتياطي واستعادته = Production Readiness Gate (B6) | لا فحص اتساق | يحوّل الحد B6 إلى شيء مُقاس: نعرف بالضبط ماذا يغطي الـdump (الصفوف وبيانات الكائنات الوصفية) وماذا لا يغطي (البايتات) |
| **E10** | اعتمادية الرفع وحدّ CI | (أ) **`python-multipart`** لاستقبال `multipart/form-data` في FastAPI — اعتمادية صغيرة قياسية (تتطلبها FastAPI لأي رفع ملف) **تحتاج اعتمادك**؛ (ب) اختبارات Storage الحقيقية (رفع، رابط، تعويض) بعلامة pytest `storage` **تُشغَّل محلياً** مع `storage-api`؛ في CI تُستبعد صراحةً بـ`-m "not storage"` **وتظهر في الملخص كمستبعدة** — لا تخطٍّ صامت؛ كل ما في DB (الجداول، الدالتان، RLS، الاتساق) يبقى في CI كاملاً | (أ) JSON بـbase64 بلا اعتمادية (حجم +33%، 1MB ← ~1.4MB)؛ (ب) تشغيل `storage-api` في CI | (أ) base64 يعمل لكنه غير قياسي ويضاعف الذاكرة؛ (ب) معتمد في B6 أنه غير مشروط — يمكن إضافته لاحقاً دون تغيير الكود |

## 2. النموذج

### 2.1 `school_profiles` — [S] (B2، E1)

| العمود | النوع | ملاحظات |
|---|---|---|
| `id` | uuid | PK — T7 يسجّل `entity_id` منه كبقية الجداول (تنفيذ) |
| `school_id` | uuid | **فريد** و FK → `schools` (1:1) |
| `address` | text | اختياري |
| `phone_e164` | text | اختياري؛ CHECK E.164 (`^\+[1-9][0-9]{7,14}$`، الثابت 12) |
| `email` | text | اختياري؛ CHECK صيغة بسيطة |
| `website` | text | اختياري؛ CHECK يبدأ بـ`https://` |
| `principal_display_name` | text | اختياري — للعرض فقط، ليس هوية ولا صلاحية |
| المشتركة | | T6/T7 |

الإنشاء كسول: أول `PUT` يُنشئ الصف. الكتابة `school.update`؛ القراءة `school.read`؛ المدرسة المؤرشفة للقراءة فقط (حارس).

### 2.2 `school_assets` — [S] (B3، E2–E4)

| العمود | النوع | ملاحظات |
|---|---|---|
| `id` | uuid | PK — يولده FastAPI؛ جزء من المسار (E4) |
| `school_id` | uuid | FK → `schools` |
| `kind` | text | `logo` \| `stamp` \| `signature` |
| `signer_title` | text | إلزامي للتوقيع وممنوع لغيره |
| `object_path` | text | فريد؛ CHECK = `{tenant}/{school}/{kind}/{id}.{ext}` حرفياً (يُتحقق في الدالة مقابل الصف، وبنية ثابتة بـCHECK) |
| `content_type` | text | `image/png` \| `image/jpeg` |
| `byte_size` | integer | 1..1048576 |
| `width`, `height` | integer | 1..4000 |
| `sha256` | text | 64 hex |
| `status` | text | `active` \| `retired` — **نهائي** |
| `retired_at` | timestamptz | يُملأ عند التقاعد فقط |
| المشتركة | | T6/T7 |

**القيود:** فهرس فريد جزئي — نشط واحد لكل `(school_id, kind)` للشعار والختم، ولكل `(school_id, lower(btrim(signer_title)))` للتوقيع؛ CHECKs أعلاه. **لا منح INSERT ولا UPDATE للعميل** — الدالتان وحدهما (B4)؛ SELECT تحت RLS.

### 2.3 RLS والصلاحيات

| | قراءة الصف | الإنشاء/التقاعد | الرابط الموقّع |
|---|---|---|---|
| `school_profiles` | `school.read` | `school.update` | — |
| `school_assets` — `logo` | `school.read` | `school.update` | `school.read` |
| `school_assets` — `stamp`/`signature` | `school.read` | **`security.manage`** | **`security.manage`** (+ تدقيق) |

كلها + `can_access_school(school_id)`. **لا مفتاح جديد** — الكتالوج يبقى 75.

**`storage.objects`: لا سياسة لأي دور عميل** (`anon`/`authenticated`) على الـbucket `school-assets` ⇒ لا قراءة ولا كتابة مباشرة عبر Storage API بجلسة المستخدم؛ الخدمة وحدها بمفتاحها.

## 3. الدوال المتحكَّم بها

| الدالة | العقد |
|---|---|
| `app.register_school_asset(id, school, kind, signer_title, object_path, content_type, byte_size, width, height, sha256, reason)` | الصلاحية حسب النوع (B5)؛ النطاق؛ المدرسة `active`؛ المسار = `{tenant}/{school}/{kind}/{id}.{ext}` مشتقاً في DB من صف المدرسة (لا من العميل)؛ إحالة النشط السابق من النوع/الصفة نفسها إلى `retired` **في العملية نفسها**؛ سبب؛ T7 + صف domain |
| `app.retire_school_asset(asset, reason)` | الصلاحية حسب نوع الأصل؛ النطاق؛ `active → retired` فقط؛ سبب؛ التدقيق. الكائن لا يُمس (E3) |
| `app.authorize_asset_url(asset)` | للخادم قبل إصدار الرابط: الصف مرئي + صلاحية الرابط حسب النوع (E7) ← يعيد `object_path`؛ للختم/التوقيع يكتب صف التدقيق في المعاملة نفسها (E8) |
| `app.school_asset_consistency()` | داخلية (بلا EXECUTE لأدوار الـAPI): صفوف بلا كائن + كائنات بلا صفوف في الـbucket (E9) |

## 4. FastAPI و Storage

- **مفتاح Storage:** وحدة جديدة `storage_admin.py` — **الموضع الثاني** الذي يقرأ `SUPABASE_SECRET_KEY` (الأول `auth_admin.py`)؛ يُوثَّق هذا صراحةً في `F4_API_SECURITY.md`. المفتاح لا يغادر الخادم (الثابت 14).
- **المسارات:** `GET/PUT /schools/{id}/profile` · `GET /schools/{id}/assets` (البيانات الوصفية، بلا روابط) · `POST /schools/{id}/assets` (multipart: `kind`، `signer_title?`، `reason`، `file`) · `POST /assets/{id}/retire` `{reason}` · `GET /assets/{id}/url` ← `{url, expires_in: 60}`.
- **الـbucket:** `school-assets`، `public = false`، `allowed_mime_types = [image/png, image/jpeg]`، `file_size_limit = 1MiB` — طبقة ثانية خلف تحقق الخادم؛ يُنشأ من `config.toml` محلياً.
- **الأخطاء:** نوع/حجم/أبعاد ← `422`؛ بلا صلاحية ← `403`؛ مدرسة غير مرئية ← `404`؛ فشل Storage ← `503` بلا أثر في DB.

## 5. الواجهة

قسم «ملف المدرسة» في صفحة المدرسة: البيانات (تعديل بـ`school.update`)؛ الأصول النشطة (معاينة الشعار للجميع؛ **معاينة الختم والتوقيعات لمن يملك `security.manage` فقط** — والخادم هو الحكم)؛ رفع نسخة جديدة بسبب؛ سجل النسخ (المتقاعدة بتاريخها). الرابط الموقّع يُطلب عند العرض ولا يُخزَّن.

## 6. الاختبارات (Gate)

- **pgTAP (CI):** العزل والقراءة ≠ الكتابة؛ الصلاحية لكل نوع (ختم بـ`school.update` وحده ← رفض)؛ نشط واحد لكل نوع/صفة؛ الإحالة الذرية؛ التقاعد نهائي؛ المسار المشتق في DB (مسار لمدرسة أخرى ← رفض)؛ المدرسة المؤرشفة؛ `authorize_asset_url` لكل نوع ودور + صف التدقيق؛ الاتساق (صفوف `storage.objects` مُدرجة يدوياً)؛ لا منح كتابة للعميل؛ لا سياسة `storage.objects` للعميل.
- **pytest (CI، بلا Storage):** الملف، التحقق من البايتات (PNG/JPEG حقيقيان، SVG، نوع مزوّر، حجم، أبعاد) — بلا رفع.
- **pytest `storage` (محلياً):** رفع ← قراءة بالرابط ← انتهاؤه؛ فشل الدالة ← لا كائن؛ فشل الـcommit ← حذف تعويضي؛ الختم بلا `security.manage` لا يرفع بايتاً؛ الاتساق بعد كل فشل.
- **Playwright (محلياً مع Storage):** رفع شعار ومعاينته؛ السكرتير لا يرى معاينة الختم.
- **ضوابط سلبية** لكل شرط؛ **الحراس الدائمة** (`11`، `13` = 39 جدولاً، `20`، `31`)؛ الاستعادة.

---

## 7. ما لا يدخل 2B-4

إثبات backup/restore الإنتاجي للملفات وسياسة الاحتفاظ/الإتلاف (**Production Readiness Gate** — B6)؛ تركيب الشهادات ولقطاتها (المرحلة 6)؛ صور الطلاب والمستندات (المرحلة 4)؛ إعادة ترميز الصور (E6 — قرار لاحق إن لزم)؛ CDN أو روابط عامة.
